# Contributing to gotenv

Thank you for your interest in contributing to `gotenv`! We welcome bug reports, feature requests, documentation improvements, and code contributions.

## Getting Started

### Prerequisites

- [Go](https://go.dev/) 1.23 or newer
- [Git](https://git-scm.com/)
- `make` (optional, for helper targets)

### Setting Up Your Local Environment

1. **Fork and clone the repository:**
   ```bash
   git clone https://github.com/adampatterson/gotenv.git
   cd gotenv
   ```

2. **Download dependencies:**
   ```bash
   go mod download
   ```

3. **Build the binary:**
   ```bash
   go build -o gotenv .
   ```

4. **Verify installation:**
   ```bash
   ./gotenv --help
   ```

## Project Structure

- `cmd/`: CLI commands implemented using [Cobra](https://github.com/spf13/cobra) and terminal UI rendering with [Lip Gloss](https://github.com/charmbracelet/lipgloss).
- `pkg/gotenv/`: Core library for reading, writing, parsing, and formatting `.env` files while preserving comments and order.
- `internal/tools/docgen/`: Generator for markdown CLI documentation in `docs/cli/`.
- `docs/cli/`: Autogenerated CLI documentation.

## Development Workflow

### Running Tests

Run the full test suite across all packages:

```bash
go test ./... -v
```

Ensure all tests pass before submitting a pull request. When adding new features or fixing bugs, include accompanying unit and integration tests in `cmd/cmd_test.go` or `pkg/gotenv/gotenv_test.go`.

### Generating Documentation

If you add, modify, or remove CLI commands or flags, update the documentation generator output:

```bash
make docs
```

Ensure the autogenerated markdown files in `docs/cli/` and examples in `README.md` match your changes.

### Code Style Guidelines

- **Format:** Format all Go code with `go fmt ./...`.
- **Dependencies:** Avoid unnecessary external dependencies.
- **CLI Output:** Keep terminal output consistent with the existing Charm / Lip Gloss styling patterns found in `cmd/ui.go`.

---

## Submitting Pull Requests

1. Create a feature branch for your changes:
   ```bash
   git checkout -b feature/your-feature-name
   ```
2. Make your changes, write tests, and ensure all checks pass:
   ```bash
   go fmt ./...
   go test ./...
   make docs
   ```
3. Commit your changes with clear, concise commit messages.
4. Push your branch to GitHub and open a Pull Request against the `main` branch.
5. Provide a clear description in your PR detailing what was changed and how it was tested.

---

## Reporting Issues

If you find a bug or have a suggestion:
- Check existing issues to see if it has already been reported.
- Open a new issue with a clear title, description, expected vs. actual behavior, and steps to reproduce.
